# 悦享金币 · v0.5.0趣玩整合体验版

本分支 `codex/yuanxiang-entertainment` 整合每日趣答、数字合成、记忆翻牌，以及签到、红包群叠包、宝箱、福袋、金币、补贴、演示提现、邀请与基础风控。**从首页或红包群进入趣玩大厅，核心玩法无需观看广告；原有金币玩法保留。**

这是独立开发的相似玩法版本，不是元享官方产品。已参考用户提供的两张红包群照片，但未取得其源码、完整页面或内部规则，不能声称像素一致、算法一致、已符合全部微信规则或保证不封禁。工作名称及素材权利需发布前核验。

**先看[趣玩整合验收](docs/趣玩整合验收.md)**：整合功能、实际验收、截图与未完成能力。Windows可双击`start-review.cmd`；[趣玩部署与维护](docs/趣玩部署与维护.md)包含安装、Docker、升级、备份与恢复。旧版源码和本机配置保留。

**红包UI已改为两步打开**：点击聊天封面，弹出带大号金色“开”字的红色红包；点“开”后才开始开发模拟，完成后展示实际入账结果。[查看改版截图与说明](docs/红包开封UI.md)。原生和浏览器同步实现。

## 下载与启动

使用本分支源码，安装Node.js 24或更新版本，在包含package.json的项目根目录执行：

```bash
npm run setup
npm run doctor
npm start
```

无需npm install。默认只监听本机8792端口：

- 用户端：本机8792端口的 `/`。
- 运营后台：同服务的 `/admin`。
- 后台令牌：根目录 `.env.yuanxiang` 中的ADMIN_TOKEN，仅本机查看，不公开或提交。
- 微信开发者工具导入 **`miniprogram`** 目录，接口默认本机8792。

Windows如npm.ps1被执行策略阻止，可使用npm.cmd替代npm。保持服务命令窗口运行；要停止该服务用Ctrl+C。

setup生成独立 `.env.yuanxiang`，数据库独立保存为 `data/yuanxiang.sqlite`。已有 `.env`、`.env.wanfan` 及旧数据库不覆盖、不迁移。错误指向其他产品数据库时会拒绝启动。再次运行setup保留原配置。

## 先体验主流程

从首页“进入趣玩大厅”可玩每日5题、数字合成及16格记忆翻牌；保存个人进度、查看解析和复习错题。初始60道题由项目自编，按日期抽取，不依赖实时外部API，不会自动增加新题；运营可在后台持续补题并审核发布。游戏成绩由服务端动作计算，不兑换金币或现金，不展示虚构多人榜单。

下列为保留的原有金币主线：

1. 初始账户为0金币，没有虚假赠送资金。
2. 首页点击“模拟签到”，确认明确的3秒模拟，完成后签到奖励与补贴分别入账。
3. 底部“红包”进入聊天式红包群：顶部金币与提现、系统消息、横向红包卡、左侧悬浮福袋。等待120秒，或用明确标识的开发工具推进一轮。
4. 查看390金币；点击右上角×暂存，再推进一轮，金额变780。可以继续叠到本轮8888上限。
5. 打开红包或宝箱时锁定金额。取消或超时保留已叠金币；模拟完成后入账，开启新一轮。
6. 福袋每60秒一次机会，显示实际开发概率。结果由服务端锁定，领取前不公开，取消也进入冷却。
7. 金币钱包可创建演示提现申请，先冻结。后台可以通过、驳回退款或“模拟完成（不付款）”。
8. 邀请页可分享或绑定真实单层关系，不生成现金返佣；客服页可提交申诉，后台实际回复。

以上金额、概率和节奏为本版可配置的开发规则，不代表元享实际算法。明确范围见 [元享式功能范围](docs/元享式功能范围.md)。

## 广告与付款的实际状态

- `APP_ENV=development` 与 `AD_PROVIDER=demo`：提供显式模拟流程，3秒只用于接口联调，不证明任何广告被真实观看。
- `APP_ENV=production` 与 `AD_PROVIDER=disabled`：关闭开发登录、模拟发奖、推进计时和模拟付款；真实广告任务和提现创建也会拒绝。
- 激励、横幅、插屏、原生广告单元：未接入；没有假曝光、广告收入或自动弹屏。
- 微信登录：服务器交换代码及受控上游测试已提供，真实微信调用仍需AppID/密钥和网络验证。
- 激励视频SDK：独立客户端适配器已编写并以SDK替身测试，未接生产发奖；完整关闭事件不是服务端观看证明。
- 微信零钱转账、现金激励准入、随机现金奖励及推广返佣适用规则：尚未确认或接入。

当前会话此前访问微信运营、广告及支付官网返回代理403。官方接口存在不能代替业务许可。取得权限后仍需实现和验证官方适配器，不能靠后台参数开启真实广告或付款。详见 [接入与部署](docs/元享式接入与部署.md)。

Git用户在本项目根目录执行：

```bash
git fetch origin
git switch codex/yuanxiang-entertainment
git pull --ff-only
npm run setup
npm start
```

先停止自己之前启动的服务，再启动新版。已有源码改动请先保存；不要覆盖.env.yuanxiang或data目录。ZIP用户在GitHub选择本分支，点Code → Download ZIP，解压到独立目录后按上面“下载与启动”操作。原生导入miniprogram后重新编译；浏览器强制刷新。

五栏依次为：首页、红包、视频、邀请、我的。“视频”目前承载显式模拟的视频激励任务与福袋，不是短视频内容平台。红包群包含多个活动助手轮流发布的运营消息、金币红包/宝箱和本账户系统动态；助手带明确标识，不包含多人实时聊天或伪造群友提现宣传。群人数来自已注册账户数，明确区别于在线人数。群内信息流和底部横幅按前台时间错开预览：开发默认首次15/45秒，关闭后冷却120秒，每会话6次、本机每日20次；后台可配置。插屏关闭。尚未接入广告组件，不计曝光或收入。详见[等待期广告节奏与官方核实](docs/等待期广告节奏与官方核实.md)。

## 在后台管理头像和群消息

进入`/admin`登录，在“群角色与消息管理”中先添加助手昵称并从6款原创头像中选择，再添加文字、金币红包或宝箱消息，设置间隔、排序和启用状态。列表支持编辑、停用、删除；保存到数据库并进入审计。前台通过5秒轮询获取实际发布记录。

当前每条运营消息关联既有奖励池，消息数量不会增加虚假的可领取金币；旧卡片合并为历史，避免重复领取。编辑影响未来发布，停用或删除撤下关联消息，已叠金币保留。详见[群角色与消息管理](docs/群角色与消息管理.md)。
