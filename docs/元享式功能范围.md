# 元享式微信小程序开发范围

基于用户描述开发同类功能，工作名称“悦享金币”。非元享官方产品，不使用其商标、素材或未获得的源码。用户已提供两张红包群照片，本次据此实现聊天流、横向红包、固定余额与提现、悬浮福袋和五栏导航。未取得完整录屏和公开规则，不能声称逐屏一致或内部算法一致。

## 叠包的明确规则

开发默认：进入群后红包与宝箱分别每120秒增加390基础金币，每池上限8888。用户可以关闭领取提示继续等待。同一池创建广告任务时锁定当前金额；取消或超时保留叠包金额，完成后清零并开始下一轮。补贴在创建任务时固定。

这是用于实现已描述交互的开发定义，不能说是元享实际算法。离开页面后按服务端时间计算累计，预算不足时暂停新增；已展示可领金额需有预算预留，不能后台任意减掉。不同日期预留分别记账，避免跨日重复扣减。

福袋开发概率：80金币60%、120金币25%、200金币12%、500金币3%；另加固定补贴。均为可配置开发假设，不是元享真实数据。任务创建时服务端锁定结果，领取前不暴露结果以免挑奖。取消也保留冷却。没有付费抽取、现金或实物兑付。

## 商业能力与缺口

依据此前2026-10-25查询：微信运营、广告及支付官网当前会话返回代理403。官方类型定义可核实激励视频接口及isEnded客户端事件，不能证明可提现金币场景获准。真实广告、单次收益、平台观看凭据及微信转账未接入。

不宣称“已完全合规”“不封号”或“与元享一样盈利”。现金奖励必须另外核实业务规则与支付场景；不能用更名、实物或外部提现绕过限制。

## 红包群照片对应交互

- 顶部固定：红包群01、注册账户总数、账户实际金币、演示提现入口。没有照抄照片中的群号38、人数2745或金币694。
- 中间消息流：群公告、个人任务动态、红包和宝箱卡。自己的真实记录带时间；公告和准备中的卡片标为系统，不伪装成其他用户发言。
- 红包卡：橙红封面、可见待领金币、打开入口、右上角×暂存。宝箱为紫色，底部显示本轮倒计时和进度。
- 每个奖励池只有一张当前卡片。旧390、780等金额作为历史消息，不能重复开启；领取后生成新一轮等待卡。消息窗口只保留最近12条事件，但不会因此丢掉当前待领卡。
- 左侧福袋常驻，点击切到视频/福袋。底部首页、红包、视频、邀请、我的五栏，原生和浏览器一致。
- 等待期间按前台时间调度信息流和横幅位置预览，可关闭、冷却、限次；插屏关闭。没有真实投放、平台曝光或收益，详见等待期广告节奏与官方核实。
- 本次不实现未经用户同意的公开聊天、伪造聊天好评、虚假到账、盗用截图头像与宣传素材。

浏览器已实际截图；原生代码通过结构与逻辑检查，尚未在微信工具或真机验证。
