# 元享式微信小程序开发范围

基于用户描述开发同类功能，工作名称“悦享金币”。非元享官方产品，不使用其商标、素材或未获得的源码。未提供元享截图、录屏和公开规则，因此不能声称像素一致或内部算法一致。

## 本次必须匹配的主线

| 元享观察 | 本版实现目标 | 边界 |
|---|---|---|
| 签到先看激励广告 | 独立签到广告任务，成功后每日一次记账 | 开发模拟显式标记；生产关闭，未通过真实广告验证不能发奖 |
| 两分钟推送红包/宝箱 | 红包群、服务端倒计时、真实个人系统消息 | 不伪造聊天用户、在线人数或别人到账 |
| 关闭低金额包，继续叠包到8888 | 待领取金额、暂不打开、继续叠加、可配置上限 | 群生成节奏、初始390及上限8888为本版开发规则，未核实元享算法 |
| 宝箱倒计时 | 红包和宝箱的独立奖励池与可见进度 | 等待不等于广告播放；页面退出后按服务器时间恢复 |
| 一分钟福袋 | 服务端冷却、概率披露、随机金币、领取记录 | 仅开发模拟；未认定随机现金激励符合微信规则 |
| 金币和补贴 | 基础奖励、补贴、预算预留、流水、任务幂等 | 不虚构“手机权重API”或单次收入 |
| 微信零钱提现 | 演示申请、冻结、审核、驳回、模拟完成 | 实际转账未接入，没有虚假到账 |
| 风控 | 总/分类型次数、冷却、账户限制、任务防重、审计和申诉 | 基础规则风控，不冒充元享的商业反作弊系统 |
| 推广 | 邀请码、单层绑定、真实邀请记录和微信分享入口 | 无现金返佣、多级分销、强制分享 |
| 广告种类 | 预留激励、横幅、原生与插屏的位置和能力状态 | 未获准的广告关闭，不模拟广告曝光或收益 |

## 叠包的明确规则

开发默认：进入群后红包与宝箱分别每120秒增加390基础金币，每池上限8888。用户可以关闭领取提示继续等待。同一池创建广告任务时锁定当前金额；取消或超时保留叠包金额，完成后清零并开始下一轮。补贴在创建任务时固定。

这是用于实现已描述交互的开发定义，不能说是元享实际算法。离开页面后按服务端时间计算累计，预算不足时暂停新增；已展示可领金额需有预算预留，不能后台任意减掉。不同日期预留分别记账，避免跨日重复扣减。

福袋开发概率：80金币60%、120金币25%、200金币12%、500金币3%；另加固定补贴。均为可配置开发假设，不是元享真实数据。任务创建时服务端锁定结果，领取前不暴露结果以免挑奖。取消也保留冷却。没有付费抽取、现金或实物兑付。

## 商业能力与缺口

依据此前2026-10-25查询：微信运营、广告及支付官网当前会话返回代理403。官方类型定义可核实激励视频接口及isEnded客户端事件，不能证明可提现金币场景获准。真实广告、单次收益、平台观看凭据及微信转账未接入。

不宣称“已完全合规”“不封号”或“与元享一样盈利”。现金奖励必须另外核实业务规则与支付场景；不能用更名、实物或外部提现绕过限制。
