# 元享式玩法：接入与部署

本文件为v0.3历史说明。当前版本使用codex/yuanxiang-v1-review分支，安装、公开配置、Docker、备份与恢复请看[部署与维护v0.4](部署与维护-v0.4.md)。

## 本机与微信工具

安装Node.js 24，项目根目录执行npm run setup、npm start。本版使用独立.env.yuanxiang和data/yuanxiang.sqlite，端口8792。浏览器用户端路径/、后台/admin。ADMIN_TOKEN仅从本机配置读取。

微信开发者工具导入根目录的miniprogram。游客AppID只适用于工具支持的开发体验；取得企业AppID后替换project.config.json。当前没有执行微信工具或真机编译。开发工具本机可不校验合法域名；正式版本恢复urlCheck并设置自己的HTTPS合法域名。

手机的127.0.0.1指手机自己。可信局域网测试需显式设置后端HOST=0.0.0.0、客户端改为电脑局域网IP，并按微信工具支持的方式调试。不要把开发身份登录服务直接公开用于现金经营。

## Linux服务器内部体验

在安装Node.js 24和Git的服务器中执行：

```bash
git clone --branch codex/yuanxiang-miniapp --single-branch https://github.com/yuge813/vx.git yuanxiang
cd yuanxiang
npm run setup
npm start
```

默认仅监听本机。在自己的电脑建立SSH连接：

```bash
ssh -N -L 18792:127.0.0.1:8792 用户名@服务器IP
```

保持连接，电脑浏览器访问本机18792端口的/和/admin。长期运行需按自己的服务器选择进程守护；当前没有对用户服务器执行部署。

HTTPS反向代理时设置.env.yuanxiang中的PUBLIC_ORIGIN，例如https://你的域名，不带末尾斜线。不能通过允许任意Origin修复跨站错误。后端使用单实例SQLite和单进程限流，不作大规模容量承诺，反向代理后的可信IP策略和分布式方案需要独立设计验证。

迁移和备份时先停止自己管理的服务，再完整备份数据库及可能存在的WAL/SHM文件，或使用SQLite在线备份接口；不应在写入中只拷贝主文件并认为备份完整。密钥文件不进入Git。

## 接入微信广告前

1. 注册并核实企业主体、类目、适用备案及流量主要求。
2. 如实提交完整玩法：签到看广告、红包/宝箱叠加、随机福袋、金币兑换现金、补贴来源和提现条件。
3. 确认奖励类型、展示和频次适用规则，不能用APP的行为推定小程序获准。
4. 核实实际产品是否提供服务端观看验证及任务关联；客户端isEnded、本地计时或业务签名不能冒充平台凭据。
5. 若没有可靠的逐次收益接口，不能宣传按实时广告收益或手机商业权重精准分成。
6. 获准后开发实际适配器、广告单元及取消/无填充/重复通知/断网恢复，不将显式开发模拟搬到生产发钱。

## 接入微信付款前

现有企业商户号不代表广告奖励转账场景已获准。需核实商家转账用途、资质、主体关联、实名和额度要求。接入官方服务端下单、用户确认（适用时）、验签通知、主动查单及渠道账单对账。

提现必须沿用原业务单号幂等；未知状态先查原单，不能重复转账或过早退回冻结。demo_paid明确表示模拟完成，不能迁成真实已到账。演示账户和金币不转换为真实用户资金。
