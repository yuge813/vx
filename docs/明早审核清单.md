# 明早先看这份 · v0.4.0内部审核版

源码分支：`codex/yuanxiang-v1-review`。原`codex/yuanxiang-miniapp`及更早版本保留，没有覆盖本机密钥、旧配置或用户数据库。默认产品仍是签到、金币、聊天式红包群，不是菜谱。

## 5分钟检查

1. Windows安装Node.js 24后，双击根目录`start-review.cmd`；其他系统在项目根目录执行`npm run setup`、`npm run doctor`、`npm start`。
2. 浏览器打开本机8792端口，首页模拟签到。原生微信工具导入`miniprogram`目录；游客配置只供工具支持的开发体验。
3. 进入红包群，等待或用开发工具推进120秒。查看390→780→8888、关闭暂存、取消保留、成功入账和下一轮。
   点击红包封面现在先出现带金色“开”字的红包面板，点“开”才启动模拟；完成后显示领取结果。见[红包UI截图](红包开封UI.md)。
4. 等待期间查看不同活动助手的昵称与头像，以及15/45秒错开的广告位预览。它们明确标为开发预览，不加载真实广告、不产生收益。
5. 打开`/admin`，从本机`.env.yuanxiang`读取ADMIN_TOKEN登录。先看“群角色与消息管理”，新增助手及消息，再回前台验证轮播。
6. 后台下方查看经营报表、账务核对、用户查询、注销申请。现金账单是人工记录，开发金币与现金分开。
7. “我的→账户与隐私”可改昵称、导出最近JSON、退出所有会话和提交注销申请；有余额、冻结或任务时先处理权益。需要人工处理小额遗留权益时走客服，不会自动扣掉用户余额。

## 必须保留的上线门槛

1. **微信规则与业务准入未确认。** 本轮读取微信运营、激励广告及支付官方页面仍返回代理403。看广告换可提现金币、随机奖励、推广等具体场景需要取得当前有效官方依据，不能因为竞品APP这样做就认为小程序获准。
2. **企业小程序与微信登录未真机验证。** 需注册并配置自己的AppID、密钥及合法HTTPS域名。`npm run configure:mini`只写公开配置，不验证权限；体验版/正式版前端会拒绝本机或开发后端。
3. **真实广告及金币发奖链路尚未接通。** 有独立激励视频SDK客户端适配器和模拟测试，未接生产发奖路径。`isEnded`仅客户端事件，不能当服务端观看证明，更没有单次收益或手机商业权重接口。
4. **微信零钱真实转账未接入。** 现有商户号不等于商家转账场景获准；还需产品权限、用途、实名、通知验签、查单与渠道对账的真实实现和验证。当前只能冻结、审核、驳回和明确的模拟完成。
5. **生产运营资料待填写。** 企业隐私声明、联系方式、保留期限、注销余款处置、投诉与内容审核、名称和素材权利需经营主体确认。本次是内部审核代码，不是已通过微信审核的商业版本。

这些门槛都已在配置、界面或服务端保留关闭/阻断；没有审核后切换、伪造到账或隐藏违规功能的机制。

## 运行结果与限制如何理解

内部审核版的前后端可以运行并检验完整业务；不能据此承诺已能靠广告经营、真实发钱或永不封禁。商业设备反作弊、多管理员权限体系、渠道财务对账和规模容量不在本次验证结论内。后续投入应先解决上述准入与真实接口门槛。
