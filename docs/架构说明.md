# 架构与API

## 数据流程

原生小程序和浏览器客户端共用 Node.js HTTP API。SQLite事务负责余额、冻结、流水、任务与预算的一致性。当前适合单实例开发演示，不应直接用于大规模生产。

所有用户接口从Bearer会话识别当前用户，不接受请求中的用户编号来选择扣款账户。会话数据库只保存令牌SHA-256摘要。管理接口另用至少32字符随机令牌，默认不开启匿名管理员。

## 接口

| 方法及路径 | 内容 |
|---|---|
| GET /api/health | 服务与真实能力状态 |
| GET /api/config | 公开奖励规则及开发能力开关 |
| POST /api/auth/demo | 开发登录，installationId |
| POST /api/auth/wechat | 微信临时code由服务端交换登录态 |
| GET /api/me | 当前账户、余额、签到、冷却和服务器时间 |
| POST /api/checkin | 幂等每日签到 |
| POST /api/tasks | 创建kind为chest/bag/signin_bonus的演示任务 |
| GET /api/tasks/:id | 查询本人任务与固定奖励 |
| POST /api/tasks/:id/complete | 仅开发模式可用的模拟完成 |
| POST /api/tasks/:id/cancel | 取消并释放预留 |
| GET /api/ledger | 最近100条本人金币流水 |
| GET/POST /api/withdrawals | 本人订单 / 幂等演示申请，coins与requestKey |
| GET/POST /api/plans | 读取 / 添加本人计划 |
| PUT/DELETE /api/plans/:id | 修改 / 删除本人计划 |
| POST /api/dev/ready | 仅开发模式推进冷却 |
| GET /api/admin/overview | 规则、用户、预算、提现和审计概览 |
| PUT /api/admin/settings | 保存允许修改的规则项及新版本 |
| PUT /api/admin/users/:id | 限制、恢复或调整单人频次，必须填写原因 |
| POST /api/admin/withdrawals/:id/review | approve/reject/simulate_pay |

修改请求使用application/json。用户和后台会话均使用Authorization: Bearer。接口不通过URL传令牌。

## 核心约束

- 每个用户最多一个待完成广告任务；重复创建同类任务返回原任务。
- 创建时锁定基础奖励、补贴、规则版本和预算日期；不追溯修改金额。
- 每个任务30分钟有效，完成前取消或过期释放预留。过期清理在任务操作、签到、规则修改和后台读取时执行。
- 每日上限按任务创建日期计数，使用Asia/Shanghai；已承诺任务允许在有效期内跨日完成。
- 流水event_key唯一；任务状态、余额和流水在同一事务提交。
- 每笔提现的用户与requestKey唯一；相同编号不同金额会拒绝。
- 提现状态只能pending_review→approved→demo_paid或pending_review→rejected。
- 模拟完成消耗冻结额，驳回退回；重复同状态操作不重复入账。
- 不支持后台随意编辑余额或换算比例。

## 风险边界

本地3秒计时只服务开发，不是广告真实性验证。没有真实广告收入、广告平台鉴权回调、设备指纹、反作弊模型、支付网关或渠道对账。当前每IP限流仅是单进程基础保护；反向代理、分布式部署和多管理员身份需要另行设计。

服务默认仅监听本机；浏览器API按同源限制跨站请求。生产反向代理的HTTPS源站、域名和可信代理策略需正式配置，不能直接暴露演示服务。开发模式支持按安装标识重进同一演示账户，该标识不构成生产身份认证。
