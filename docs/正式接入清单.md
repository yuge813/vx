# 权限与正式接入清单

本项目采用“先完成可演示的源码，再根据具体业务核实和申请权限”的顺序。企业小程序注册、广告流量主开通、现金激励业务许可、商家转账产品开通是不同事项。源代码和演示截图不替代资质。

## 1. 企业小程序及业务规则

- 确定企业运营主体、实际服务内容和适用类目，完成当期要求的注册、验证及备案等步骤。
- 如实向平台描述：签到、定时宝箱、可选激励广告、金币兑换现金、提现条件、补贴资金来源。
- 核实是否允许以观看广告作为主要服务，金币兑换现金是否适用；同时核实倒计时、随机奖励、分享推广等机制。未取得适用依据，不按“技术接口存在”推定许可。
- 留存适用规则版本、账户权限、原型及正式反馈，避免只依据口头承诺或第三方“包过审”。

可以咨询：

> 我司拟在企业主体小程序中提供日常计划等服务，并设置用户自主参与的激励视频任务。完整观看并满足公开条件后，获得固定金币；金币拟按公开比例兑换人民币，并通过获准的官方转账能力进入微信零钱。另有签到、120秒宝箱机会和运营补贴。请确认该完整场景的适用类目、广告奖励限制及转账用途要求，并提供规则依据。若广告奖励为主要功能，是否允许？

应根据最终产品如实调整描述，不能以辅助功能掩盖真实主营业务。

## 2. 广告接入

- 在对应企业小程序账户确认最新流量主准入条件，不假设固定用户数门槛。
- 创建自己获准的广告单元，核实激励视频、Banner、插屏及原生模板的实际权限和展示要求。
- 本项目没有接入广告单元ID，展示的“广告流程”为显式开发模拟。
- 接入时先依据该产品的官方文档确认：客户端完成事件、服务端验证、任务关联、重复通知和数据报表分别有什么能力。
- 若平台没有提供可验证的逐次观看凭证，不能用客户端传来的 `isEnded`、本地时间或业务签名冒充平台证明；重新评估是否支持现金风险敞口。
- 如没有逐次收入接口，使用事先公布的固定奖励和预算，不宣传为精确的实时单次收入分成。
- 验证无广告、未完整观看、切后台、网络中断、组件审核及频控失败等情况。
- 当前代码只有 demo/disabled 两个适配器，**尚无真实广告适配器**，需要另行实现并测试。

## 3. 微信零钱转账

- 用户已有企业微信支付商户号；仍需核实商家转账当前准入、业务场景和小程序关联要求。
- 确认该转账用途适用，不能通过虚报交易场景获得权限。
- 依据实际获准产品接入服务端下单、用户确认（适用时）、验签通知、主动查单和账单对账。
- 微信 `wx.requestMerchantTransfer` 是用户确认收款能力之一，客户端成功回调不直接等同银行或微信最终资金结果。
- 服务端以原业务单号幂等处理。超时或未知状态先查原单，不重复付款，也不提前释放冻结金币。
- 失败确认后按规则退回；成功后冻结转已支付；保存真实渠道单号和审计记录。
- 当前审核按钮只可写入 `demo_paid`，不会调用转账接口，不能用于真实付款记账。

## 4. 账务、隐私和经营

- 正式现金账务与演示账户必须隔离，不允许把开发初始金币转换为真实可提现余额。
- 制定真实兑换规则、门槛、到账时效和费用说明；不能临近提现追加广告或邀请条件。
- 验证奖励履约资金、补贴上限、结算周期及异常扣量承受能力。
- 完善企业隐私指引、最小化采集、数据保留、权限、注销、客服和人工申诉。
- 将单管理员令牌升级为正式后台账户、权限分离与必要的双人审批，完成审计日志备份。
- 进行数据库迁移规划、恢复演练、压力测试、支付安全测试和故障处置。
- 原生小程序在微信开发者工具和真机完成编译与流程验证；当前尚未执行。
