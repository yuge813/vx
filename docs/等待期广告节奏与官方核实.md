## 当前已实现的节奏

以下全部是可修改的**开发位置预览参数**，不是微信规则或推荐投放频次：

| 项目 | 开发默认 |
|---|---|
| 信息流位置 | 进入红包群后累计15秒前台空闲时间首次预览，同类位置至少间隔90秒 |
| 底部横幅位置 | 累计45秒前台空闲时间首次预览，同类位置至少间隔120秒 |
| 单次位置停留 | 20秒后结束预览 |
| 不同类型间隔 | 两次位置开始预览至少相隔30秒，同时最多一个位置 |
| 主动关闭 | 立即关闭，并进入120秒跨类型冷却 |
| 频次上限 | 每会话6次、本机本账户北京时间每日20次，后台可调至0关闭 |
| 插屏 | 关闭，不随两分钟倒计时自动弹出 |

调度仅在红包群前台、没有进行或待恢复的奖励任务时累计。离开页面、切后台或开始领取任务时暂停；返回后不补算离开期间的展示。较长的页面阻塞也不会通过一次时钟跳变生成多条预览。

信息流位置在消息流内，横幅占用独立的底部空间，不覆盖红包按钮、倒计时或导航。关闭预览不会扣金币、重置叠包或阻止打开红包。取消激励任务仍按原规则保留已叠金额。

“广告预览 x/6”可打开本机节奏说明。每个位置均标明开发预览、未加载广告；没有广告主图片、伪造推广素材或虚假曝光。后台提供总开关、首次延迟、同类间隔、停留、关闭冷却及次数设置，配置写入数据库并进入已有审计。

## 可信边界与接入门槛

- `shared/ad-pacing.cjs`是同一调度源，生成浏览器`web/ad-pacing.js`及原生`miniprogram/services/ad-pacing.js`；静态检查会验证三者一致。
- 本机预览次数与关闭冷却按账户保存在本机。刷新保留日计数和冷却；清除存储、多设备或并行页面能绕过本机次数，因此它是体验控制，不能作为服务端反作弊或投放日限额。
- 当前不采集或上报广告曝光、点击、广告观看和收入。预览计数不能加入广告收益报表；金币账务完全不依赖预览计数。
- 正式环境强制`adPacing.mode=disabled`；真实banner/native/interstitial能力仍为disabled。后台打开预览开关不能开启真实广告或转账。
- 获准后必须用自己的广告单元和对应真实微信组件，按当前规则约束位置、触发与刷新，使用真实加载/失败/关闭事件管理生命周期。无填充、错误或平台频控时跳过该展示机会，不能循环立即重试，也不能影响合法奖励。
- 插屏若将来适用，应先核实允许的触发场景，再在真实页面/任务的自然节点评估；这是产品建议，当前未认定该节点必然获准。需与激励视频互斥、处理平台错误码并服从更严格的限制。
- 实际广告位置保持平台标识与组件完整，不能将原生广告按钮、关闭入口或交互区域改成业务红包，也不能把本次自绘预览当成可投放广告组件。

本机展示成功不等于广告有效计费；结算应以平台最终有效报表为依据，等待时长不计为广告收入。

## 验证方式

`npm test`覆盖前台累计、15/45秒错峰、关闭冷却、后台/奖励暂停、时钟跳变、次数上限、持久恢复和正式环境关闭；原生页面通过wx适配层与真实HTTP后端验证。浏览器回归等待实际15秒信息流和45秒横幅预览，验证关闭后仍能打开红包，再执行完整金币业务流程。微信工具、真机、真实广告及平台计费尚未验证。
