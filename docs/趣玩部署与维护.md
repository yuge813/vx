# 趣玩整合版的安装、部署与维护

适用分支：`codex/yuanxiang-entertainment`，版本`0.5.0`。这是包含每日趣答、数字合成、记忆翻牌及原红包群的内部体验版。原生小游戏形态、真实微信登录、广告和支付仍需取得权限并完成真实验证；生产环境目前强制关闭趣玩业务入口。

## 本机运行

安装Node.js 24或更新版本，解压整合源码，在项目根目录运行：

```bash
npm run setup
npm run doctor
npm start
```

无需安装运行依赖。Windows可双击`start-review.cmd`。默认监听本机8792端口，用户端路径`/`，后台路径`/admin`。后台令牌仅从本机`.env.yuanxiang`读取，不公开、不提交；已有文件会保留。

首页和红包群均有“趣玩大厅”入口。用户可完成每日5题、查看解析、复习错题、恢复数字棋盘和记忆翻牌记录。玩法不发金币或现金，不要求观看广告。它与既有奖励账本分开，游戏分数不能兑换金币。

## 微信开发者工具

导入`miniprogram`目录，趣玩页面为`pages/play/index`。原生源码与浏览器共用规则模块，业务动作仍由服务端判定。现有游客AppID只用于工具支持的开发体验，不代表可以提交正式版本。

自己的企业AppID和合法HTTPS域名获准后，公开配置可用：

```bash
npm run configure:mini -- --api https://你的接口域名 --appid 你的企业AppID
```

密钥只进入服务端环境。体验版、正式版会拒绝连接development演示后端；production后端会关闭当前趣玩原型。不能通过修改前端开关绕过。微信开发者工具编译和真机验证不在本轮可执行证据内。

## Docker与服务器内部审核

镜像固定官方Node24.19.0基础镜像摘要，无第三方运行依赖。启动进程为uid1000，根文件系统只读，数据库卷可写；镜像不含密钥、用户数据库或私有微信工具配置。

已有Docker的机器可使用仓库的Compose配置：

```bash
npm run setup
docker compose build
docker compose up -d
docker compose logs --tail=50 app
```

该配置默认只绑定宿主机127.0.0.1的8792端口，使用独立命名卷。内部远程审核需自行建立SSH端口转发。用户服务器的公网域名、HTTPS证书、实际微信权限和企业隐私资料未在本次自动配置，不把内部容器启动当作公开上线。

本轮云环境已另用独立审核容器`yuanxiang-v05-review`，只绑定本地8797，独立数据与备份卷，避开已有8792—8796监听及旧数据。实际验收结果见[整合验收记录](趣玩整合验收.md)。管理员令牌只保存在该轮私有临时配置，不写进镜像、源码或文档。临时配置若被系统清理，需要由部署者安全重建或轮换；不能假设它跨环境恢复后仍存在。管理员可使用`docker logs --tail=50 yuanxiang-v05-review`排查，只操作自己管理的容器。

## 从v0.4升级与回退

`0.5.0`只给本产品数据库增加趣玩题目、答题、错题、棋盘、动作幂等与内容版本表，已有金币余额、奖励流水、红包池及配置不迁成另一套产品数据。首次运行初始化60道开发自编题，之后不覆盖运营修改。

升级前先执行在线备份，保存旧源码版本和旧环境配置。升级后进入后台检查金币对账，再检查趣答与棋盘恢复。回退时应停止自己管理的服务，将旧代码及备份恢复到**新路径**后配置DB_PATH；不要直接覆盖仍在使用的数据库。必要的财务记录保留，不能因回退删除已发生的合法权益。

本轮已用独立临时数据库实际演练`a876c6e`版本升级：原620开发金币与2条流水保留；新答题和两个游戏状态经过在线备份、恢复后仍存在。该结论不表示已替用户实际数据库升级。

## 在线备份、恢复与运维

```bash
npm run backup
npm run restore -- backups/你的备份.sqlite data/新的恢复数据库.sqlite
```

备份使用SQLite在线接口并验证完整性；恢复拒绝已有目标及其WAL/SHM文件，不覆盖运行中的数据库。数据、备份和环境文件不要进入Git。容器内可执行`node scripts/backup.mjs`，显式指定源数据库及新目标。

趣玩没有独立现金账本。内部对账仍检查原金币账务；游戏进度和成绩使用服务端状态、revision与actionId防重复。暂停、切后台或超过正常心跳间隔不会把整段离线时间累计为游戏时长；个人娱乐记录不作商业反作弊认证。

后台题库“保存草稿”与“发布”分开；发布需核对答案、来源权利和审核依据。已有日题单保存快照，不随题目后续编辑改变。上线前仍需经营方逐题审核内容、说明数据保存期限并完成投诉处理流程。
