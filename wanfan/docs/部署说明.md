# 晚饭有谱：安装与部署

当前支持内部原型运行。真实广告、现金、实物和支付均硬关闭。配置不能把它变成已获准的商业产品。

## 本机最快运行

安装Node.js 24或更新版本，下载 `codex/wanfan-youpu` 分支，在包含package.json的项目根目录执行：

```bash
node -v
npm run setup
npm start
```

无需npm install。服务默认只监听本机8790端口。浏览器体验端路径 `/`，运营后台路径 `/admin`。管理员令牌在 `.env.wanfan` 的 `ADMIN_TOKEN`，只在本机查看；不要公开、提交或放进小程序。

Windows如npm.ps1被执行策略阻止，可使用 `npm.cmd run setup` 和 `npm.cmd start`，无需修改系统策略。

`.env.wanfan` 和 `data/wanfan.sqlite` 与旧版 `.env`、`data/xingxiang.sqlite` 独立；setup不会覆盖现有配置。重启保留库存、菜单、签到及反馈，不导入旧金币。

## 微信开发者工具

1. 导入 **`wanfan/miniprogram`** 目录，而不是旧版的miniprogram目录。
2. 游客AppID只用于工具支持的开发体验，申请企业AppID后再配置自己的项目。
3. 默认API地址在 `wanfan/miniprogram/config.js`，指向本机8790端口。
4. 开发工具本机测试可关闭合法域名校验；正式环境恢复project.config.json的urlCheck并配置HTTPS合法域名。
5. 真机的127.0.0.1是手机自身。可信局域网测试需显式设置后端HOST=0.0.0.0，并将客户端API改为电脑局域网地址；不要将内部开发登录服务直接公开经营。

当前未运行微信开发者工具或真机编译。Node的wx适配层测试和WXML静态检查不能替代这些步骤。

## Linux服务器内部测试

先安装Node.js 24、Git。在自己的服务器执行：

```bash
git clone --branch codex/wanfan-youpu --single-branch https://github.com/yuge813/vx.git wanfan
cd wanfan
npm run setup
npm test
npm start
```

内部测试保持HOST=127.0.0.1。在自己的电脑建立SSH端口转发：

```bash
ssh -N -L 18790:127.0.0.1:8790 用户名@服务器IP
```

在电脑浏览器访问本机18790端口的 `/` 与 `/admin`。不要把服务器IP的8790端口直接作为正式小程序后端。

## 进程守护与HTTPS候选配置

`deploy/wanfan.service.example` 为systemd模板，`deploy/nginx.conf.example` 为Nginx模板，**尚未在你的服务器执行**。需要根据实际Node路径、服务账户、安装目录、域名和证书修改。内部原型优先使用前述SSH方式。

正式部署的基础配置示例：

```dotenv
APP_ENV=production
HOST=127.0.0.1
PORT=8790
DB_PATH=./data/wanfan.sqlite
PUBLIC_ORIGIN=https://你的实际域名
ADMIN_TOKEN=在服务器安全生成的随机管理令牌
WX_APP_ID=你的小程序AppID
WX_APP_SECRET=仅服务器保存的应用密钥
```

PUBLIC_ORIGIN不带末尾斜线。HTTPS反向代理时必须配置它，后端才能正确验证浏览器Origin；不能通过放开所有跨站来源来修复。原生微信请求仍使用合法域名。

production关闭开发安装标识登录及内部权益授予。浏览器体验端不提供正式微信身份登录；正式微信登录在小程序中完成，需实际网络验证。后台不依赖用户端开发登录。

模板配置前需确保服务账户存在、Node路径正确、data目录归该账户可写、配置文件仅服务账户可读。Nginx模板替换真实域名和证书后，先执行nginx -t，再根据机器管理流程加载。不要覆盖服务器已有站点。

后端当前为单实例SQLite和单进程限流。反向代理后请求会共享来源IP的限额；若公开规模化运行，需要单独完成可信代理、分布式限流、容量和备份设计。没有完成这些验证，不作生产容量承诺。

## 数据备份和迁移

不要用测试数据覆盖旧目录。简单备份应先停止自己管理的晚饭服务，再完整复制 `data/wanfan.sqlite` 及仍存在的WAL/SHM相关文件，或者使用SQLite在线备份接口。不得在写入中只复制主文件后声称备份完整。恢复先在隔离环境检查账户、库存、菜单、会话与完整性，再切换服务。

不应将开发账户、内部测试权益当成正式用户权益。原型不存在现金余额，不存在迁移为真实资金的操作。

## 启动验证

- `/api/health` 返回product=wanfan、ok=true，realAds/realPayments均为false。
- 新账户无虚假库存及历史；加入菜单后有真实缺料。
- 完成只扣一次库存；刷新后菜单与签到保留。
- 管理后台必须鉴权，授予只在development允许。
- 广告与提现接口返回503 CAPABILITY_DISABLED，不能靠客户端伪造观看开启。
